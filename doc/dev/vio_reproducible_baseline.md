# VIO 可复现调试基线

## 当前结论

已在本机、同一修复版二进制、冻结输入和同一调试配置下，完成三次独立进程全程回放：每次 2,402 帧，位置、四元数、速度和两组 bias 的 16 个字段精确一致，原始 CSV 逐字节相同。固定采样和单线程参数本身不足；还需要修复空参考描述子被误当成一行有效数据的问题。

这是可复现的失败用例基线。三次 APE RMSE 均为 142.643151 m，精度仍差，不能宣称原局部漂移问题已解决。验证范围仅为本机、本运行包与本录制；不同机器、二进制、输入或并行配置没有在本轮验证。

## 目标与验收

同一机器、二进制、输入及配置，多次独立进程得到一致的逐帧轨迹。先比较完整输出时间戳和逐帧位姿，再检查速度及 gyro/accel bias；记录原始 CSV 哈希、逐字段精确一致性、第一处分歧及最大差。APE 接近不作为复现通过条件。严格一致未通过时明确标为失败，不自行放宽容差。

## 执行步骤

1. 分支 `feat/vio-reproducible-baseline` 基于 `cfdcae4`，保留已有子模块改动。冻结输入与上一轮已验证的二进制（`50b0c4e33ba833fa4af35255078df555bb1b367232f2fcf787ae43bacb919422`）。
2. 全部使用 `--deterministic 1`。solver-single 仅将 realtime_num_threads 从 3 改为 1；enforce_realtime 原本为 false，保持不变。独立启动三次，从原始起点处理完整录制。
3. frontend-single 在此基础上将 parallelise_detection 改为 false、num_matching_threads 从 4 改为 1。独立启动三次；保持四相机、回环和 final BA 关闭。不同时修改匹配统计或其他算法参数。
4. 记录来源、实际命令、配置、二进制/输入哈希和各次耗时；对原有 2,402 帧时间戳逐项验证。复用上一轮分析器和原 GT 帧对计算精度，复现性和精度分开报告。
5. 若配置组仍不一致，先从最早分歧记录定位，必要时补充默认关闭的逐阶段指纹或严格调度对照；任何新源码实验使用新的冻结二进制和独立运行组，不混入这六次配置对照。

## 已知边界

匹配误差当前按线程均值再平均，空分片存在除零路径。因此 frontend-single 可能改变判定，不能将其效果全部解释为消除了并发。后台优化/发布与数据读取线程仍存在；现有配置不等同于全流程串行。运行时长仅作描述，其他主机负载及缓存未受控。

- `scripts/compare_vio_states.py`：保留 int64 纳秒时间戳，比较位置、四元数、速度、陀螺与加速度 bias 的 16 个原始浮点字段；另外记录 CSV 字节哈希、首次差异和最大差异。四元数符号相反仍判原始状态不一致，几何角差单独报告。
- 42 项 Python 测试通过，其中 7 项新增测试覆盖严格比较和配置生成。六次配置对照使用上一轮冻结的 Release 程序。

## 求解器单线程组结果

三次均输出 2,402 帧，共同 GT 评估 2,401 帧；全部逐帧时间戳与原始记录一致。APE RMSE 依次为 114.873695、119.110527、121.075292 m。三组两两比较均未通过严格一致验收，位置最大差为 35.611655、41.504971、13.912147 m。

运行 1 与运行 2/3 的前 1,437 个状态完全相同，第 1,438 个输出帧（47.900839 s）首次不同。运行 2 与运行 3 到 51.934245 s 才首次不同。最初位置差约为浮点舍入量级，但后续放大；不能据此断言差异来自 Ceres，在线输出并未覆盖窗口内全部历史状态和地图点。该配置不能作为严格可复现基线，也没有改善本录制的精度。

## 后续定位：优化图指纹

前端单线程组第 2 次与第 1 次在 58.001015 s 首次产生输出状态差异，因此上述配置不足以达到目标。新增默认关闭的 `OKVIS_REPRO_AUDIT=1` 诊断：在每次实时图求解前后记录纳秒时间戳、迭代上限、参数/残差数量、按语义 ID 排列的参数数值指纹，以及 Ceres 参数枚举和残差顺序指纹。指纹不包含堆地址，不调用残差求值，避免主动改变 IMU 缓存；它是定位辅助，不替代输出逐字段精确比较，也不覆盖残差内部缓存的全部内容。

诊断版本另行构建、冻结并在独立目录运行。原六次对照结束前不进行构建或并发回放。若指纹定位到具体来源，再做单独的最小修复或严格调度对照，不将配置变化误报为已解决。

## 定位结果与修复

两次独立诊断回放位于 `results/reproducible_baseline_20260930_audit`，完整输出均为 2,402 帧。`graph_comparison.json` 显示：61.501079 s、第 1 次前端位姿求解开始前，语义参数数值指纹相同，但残差数量分别为 9,207 / 9,205，视觉测量和残差顺序指纹也已不同；求解后的参数才开始不同。之前各次求解的数值、视觉测量和残差顺序一致。对应日志中的匹配平均重投影误差为 9.9323 / 9.90854，RANSAC 内点为 215 / 197。这将该次首次分歧定位到前端约束选择，不能归因为这次 Ceres 求解的归约顺序。

在 `Frontend::matchToMap` 发现确定的未初始化数据读取路径：描述子缓冲区最多预留三条，原代码将“最大已写槽下标”初始化为 0，最后无条件使用 `o + 1` 行。当所有历史观测被视角/尺度/评分过滤时，没有描述子、射线或相机中心被写入，仍暴露一行给后续匹配。原有 `rows == 0` 分支事实上无法覆盖这个情况。于是分配器残留内容可以改变匹配约束。

修复使用实际已写槽数量，初始值为 0；零候选直接跳过，正常候选继续保留原先最优三条的选择与替换顺序。不改变图像、RANSAC 门限或种子、迭代数、关键帧窗口或线程调度。`OKVIS_FEATURE_AUDIT` 开启时记录逐相机 `DESCRIPTOR_SELECTION ... skipped_empty=...`，用于确认录制确实触发此条件。最优槽选择提取为小型共用函数，以测试空候选、NaN 评分和正常替换行为。

修复版使用 `results/reproducible_baseline_20260930_fixed` 独立运行三次，关闭重型图指纹，保留原有特征审计和空候选计数。三次完整回放均通过严格一致验收，详见下表。

验证记录：修复版 Release 构建成功，45 项 Python 测试通过，DescriptorSelection 和 DeterministicSampling 两个 CTest 目标通过；现有 IMU、重投影、位姿和齐次地图点残差测试通过。包含 GPS/子地图的综合 Ceres 测试因长时间未完成被中断，不记为通过。
