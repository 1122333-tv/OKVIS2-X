# 四相机 VIO 流水线实施与验证记录

日期：2026-09-20。状态：首版四阶段流水线及三次全段实验已完成。工程流程通过验证；当前 OKVIS 配置精度不通过且重复运行不稳定，其中两次出现严重发散。

## 📦 交付范围

已实现完整 rig → 四相机输入准备 → 冻结/重建动捕 GT → 纯 VIO → 规范轨迹 → 原生覆盖/共同时间戳 APE/RPE 的流水线。入口、依赖、参数和产物说明见[使用说明](四相机VIO流水线使用说明.md)。首轮一条命令从 prepare 跑至 compare，后续实验复用显式完成的准备和 GT。

所有实验使用 `20260916_142602_203941_DOHC2_validation_01`，Basalt 固定对照 `run_20260918T151707_4586ee`。原始 recording、交付和既有 Basalt run 未修改；本轮未创建 Git 提交。

## 🧭 发散诊断边界

首轮前约 40 s 的相对首帧位移仍约米级；45 s 约 0.95 m，50 s 约 22.7 m，60 s 约 166.8 m，80 s 约 717.6 m。GT 在同段始终为小范围运动。首次大重投影误差/RANSAC 事件约在 33.534 s，之后频繁出现。时间以首个输入组为零。

这些是失效时序证据，不是根因证明。当前没有证据把发散唯一归因于 KB4 迭代误差、mask、IMU 噪声、描述子或线程执行。未通过改动 GT、尺度对齐或挑选 final/BA 轨迹掩盖失败；未针对本 recording 调参。

首 10 s 接近静止，完整轨迹排名使用全程 SE(3)。诊断性首 10 s 对齐要求 GT 第二主轴 RMS 展布至少 1 cm，不满足时标记运动不足，避免以静止噪声确定旋转。首轮历史诊断图生成于此门槛加入前；后续 run 使用该门槛，主 APE/RPE 口径不变。

## ✅ 验证范围与后续

已通过 7 项 Python 契约测试和 2 个 C++ 回归程序，以及 300/300 帧真实短段回放。短段几乎静止，指定距离的 RPE 无帧对时明确标记不可计算，而不是记为零。

本次达成工程流水线验证；当前配置的精度不通过。下一步应固定重复失效片段，增加匹配内点数、有效地图点/三角化、视觉残差与 IMU bias 的逐帧诊断，再进行单因素实验；需额外 recording 验证任何改进。不能以这一个样例的运行或调参结果宣称泛化精度。
